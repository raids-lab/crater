---
title: 模型部署
description: 创建、查看和使用 Kthena 在线推理服务。
---

管理员完成 Kthena 控制器和 CRD 的安装后，可在平台设置的 AI 标签中启用模型部署。开关默认关闭；关闭后入口隐藏，推理接口拒绝访问，但不会删除已有部署。找不到入口时，请联系平台管理员确认配置。

## 创建和查看部署

新建部署按「模型 → 引擎与拓扑 → 角色资源 → 预检查」完成。选择平台模型或外部 hf/ms/s3 地址，再选择 vLLM 或 SGLang，以及合并推理或 Prefill/Decode 分离。vLLM 角色还可选择 Ray 多节点，因此可组合成 P/D + Ray。管理员通过 `backendConfig.kthena.enabledProfiles` 启用集群已配置的分布式组合；不可用选项显示原因。

平台模型以只读方式挂载授权目录。外部模型下载到各 Pod 的临时存储，重建时重新下载；外部 hf/ms 分布式部署要求固定 40 位 commit revision，S3 分布式模型需先保存为平台模型。私有模型凭据使用 Secret 引用，Secret 必须属于当前用户和账户；Hugging Face 下载凭据变量为 `HF_AUTH_TOKEN`。

服务组数决定整套拓扑的副本数。每个角色分别配置实例数、每实例节点数、镜像和 CPU/内存/GPU/RDMA。Entry 默认与 Worker 同规格，也可独立设置 Worker 的 CPU、内存和约束。Ray 配置要求各节点镜像和 GPU 规格一致，TP 等于每节点 GPU 数，PP 等于节点数；同一实例的节点使用反亲和约束分散到不同物理节点。P/D 的两个角色使用同一镜像、模型 revision 和一致的 tokenizer/KV 数据类型。

资源摘要与后端预检查统一按 `服务组数 × Σ[角色实例数 × (Entry 资源 + Worker 数 × Worker 资源)]` 汇总。预检查同时显示队列、配额等待状态和 ModelServing、ModelServer、ModelRoute 原生资源。提交时重新检查权限及配额；所有 Pod 通过 Volcano 调度，与训练任务共享账户队列。配额不足时以零组等待，配额释放后自动恢复准入。

模板、导入导出和克隆保留完整 roles 配置。详情按服务组、角色、实例及 Entry/Worker 查看 Pod 与日志。可调整服务组数、暂停、恢复或编辑部署；运行时允许资源总量不变的模板更新，改变资源预算需先暂停。引擎、布局、HTTP 端口、路由模型名和角色实例数固定，需要变更时使用克隆。路由修复保留原有 P/D 与引擎配置。

角色资源页展示管理员允许的运行镜像及 KV connector。私有镜像需由管理员加入对应 profile 的 `runtimeImages`。克隆会恢复节点范围与 RDMA 配置；关闭控件移除相应请求，其他节点约束和扩展资源可在展开区域单独编辑。暂停、缩容和删除后，正在退出的 Pod 继续计入配额，直到实际释放资源。

## 调用服务

使用部署详情提供的访问方式。通过 Crater 代理调用时，`model` 使用部署路由名；省略该字段时，代理自动补齐。该名称可能与模型本身的名称不同。代理支持流式响应，客户端应按服务返回的内容类型处理数据。

聊天页面支持流式输出和取消。只有完整回答会写入持久化会话。重试同一轮请求时保留相同的 `sessionId`、`clientTurnId` 和请求内容，后端会返回已保存的结果。同一会话已有进行中的请求时，新请求返回冲突；取消或超时后可重试。

普通用户只能访问其有权使用的部署和会话。请勿在问题反馈或截图中附带 Token、私有模型凭据或会话中的敏感内容。

## 持续计费与推理指标

运行中的模型按实际 Pod 的资源请求和占用时长参与平台持续结算，沿用资源单价、免费时长及账户余额规则。详情页的资源监控页同时展示累计结算和最近结算时间。请求数量和生成 token 数用于监控，不另行收费。

推理指标采用近五分钟窗口，包含成功请求率、生成 token 吞吐、首 token 延迟与端到端延迟 P95、等待及执行请求数、HTTP 错误比例。无采样显示“—”。请求率、错误比例和端到端延迟取自 Kthena Router；vLLM/SGLang 按角色展示引擎指标，P/D 总 token 吞吐取 Decode，两个阶段的请求数不相加。管理员可启用 Chart 的 `inferenceMonitoring.enabled` 和 `inferenceMonitoring.router.enabled`，并设置匹配 Prometheus 选择器的 `inferenceMonitoring.labels`。

计量每 15 秒采集，扣费按平台现有结算周期执行。删除会先持久化计量并结算，再释放 Pod 的计费保护。计费开启时，新 Pod 等待计量门控解除，删除操作等待结算保护释放；关闭计费时不添加计量门控。
