---
title: Crater-Agent
description: Configure and use the Crater platform assistant
---

Crater-Agent provides platform guidance, authorized job lists and diagnostics, and node and cluster resource queries. Portal users can query only their own jobs in the active account; changing entry points does not expand permissions. Raw logs and direct job creation, stopping, or deletion are not supported.

## Open the assistant

The Crater-Agent launcher appears in the lower-right corner by default. The side panel supports creating, renaming, deleting, and stopping conversations.

The welcome message lists available features and randomly shows three examples from a pool of 20 topics under “You might want to ask”. A new conversation draws a fresh selection, which stays unchanged while you type. Selecting an example sends the question immediately. Admin examples do not direct you to portal job-creation pages.

Turning off the floating launcher in personal settings hides this button without disabling Agent entry points provided by other pages.

## Queries and confirmations

Ask, for example, “Analyze only my five latest failed jobs” or “How many GPUs does this node have?” Automatic queries appear as collapsed tool entries above the answer. Cards after the answer request confirmation for navigation or form changes; they never submit a form. When you request multiple pages, navigation cards follow the requested order. Confirm or cancel each navigation before handling the next. Navigation-only actions do not wait for or validate form options. Confirm or cancel pending cards before sending another message.

“What jobs do I have now?” defaults to unfinished jobs. Recent records or explicit failed/completed filters query the corresponding history. A successful empty result means no jobs match that scope; paginated or omitted results are not a complete list.

Generation shows a non-expandable status for waiting, tool execution, or answer generation. It hides on completion and stops spinning on cancellation or failure. Internal model reasoning is not shown; tool cards remain expandable for results. Status is temporary page state and is not restored after a refresh or conversation switch.

When you request a new job and configuration assistance from another page, the side panel stays open after navigation confirmation and continues with a proposal based on the loaded GPU and image options. Navigation-only requests do not automatically generate proposals. If you did not specify an image, it may suggest a suitable basic Python image. If nothing can be safely matched, it explains why without an empty patch card. Form assistance changes only allowlisted fields on the current form; reopening a form requires a new proposal. Available resources are point-in-time estimates based on requests, not live utilization or a scheduling guarantee. Historical failures must be interpreted using the evidence retained for that job.

## Configure a personal model

In **Personal LLM Configuration**, enter an OpenAI-compatible API base URL, model name, and API key. Crater validates the connection before encrypting the API key. The complete key is never returned after it is saved.

- A complete personal configuration takes precedence over the platform default.
- The same login user shares one personal model configuration across portal and admin views.
- Portal and admin conversation histories remain separate.
- Removing the personal configuration restores the administrator-managed platform default.

Personal endpoints must be publicly reachable over HTTPS. Do not configure an untrusted model service or send passwords, tokens, or other secrets in a conversation.

Saving or removing a personal model configuration records an operation log available to administrators, including the operator, time, scope, and success or failure. Logs contain metadata such as whether a new key was submitted, not keys, endpoint URLs, model names, or raw requests and errors. Viewing settings or testing a connection alone does not produce a configuration-change log.

## Conversations and data

Conversation titles, messages, and generation status are stored in the Crater database and remain available after a refresh or device change. Administrators can review Agent conversations as part of platform administration, so use Crater-Agent only for platform-related content.

AI-generated content may be inaccurate. For resource changes or other high-risk operations, rely on the target, permissions, and confirmation details displayed by the platform.
