## 플랫폼 개요

Crater는 The Crater Project Team, RAIDS-Lab 에서 개발한 플랫폼입니다. 클러스터 내 컴퓨팅 리소스와 스토리지 리소스 등을 통합적으로 스케줄링하고 관리함으로써 클러스터의 안정적인 운영과 리소스 활용의 최적화를 실현합니다. 이를 통해 사용자는 클러스터 리소스를 효율적이고 편리하게 관리할 수 있습니다.

### 직관적인 인터페이스 설계

Crater 는 간결하고 사용하기 쉬운 사용자 인터페이스를 제공하며, 사용자는 그래픽 인터페이스를 통해 다양한 클러스터 관리 작업을 쉽게 수행할 수 있습니다. 예를 들어, 리소스 대시보드를 통해 클러스터 자원 사용 현황 (예: CPU 사용률, 메모리 사용량, 저장 용량 등) 을 실시간으로 확인할 수 있습니다.

작업 관리 인터페이스는 실행 중인 작업, 작업 대기열, 작업 이력 등을 표시하여 사용자가 언제든지 작업 상태를 확인하고 작업을 수행할 수 있도록 합니다.

![jobshow](./assets/jobshow.webp)

### 효율적인 자원 스케줄링

플랫폼은 작업의 우선순위, 자원 요구 사항 등에 따라 작업에 최적의 자원을 자동으로 할당하는 스마트한 자원 스케줄링 알고리즘을 채택합니다. 예를 들어, 여러 작업이 동시에 자원을 요청할 경우, Crater 는 신속히 분석하여 가장 긴박하고 중요한 작업에 자원을 할당하여 전체 실행 효율을 향상시킵니다.

### 모니터링 기능

상세한 모니터링 데이터와 로그 기록은 사용자가 클러스터 운영 상태를 깊이 있게 파악할 수 있는 근거를 제공하며, 사용자가 고장 진단 및 성능 최적화를 수행하는 데 도움을 줍니다.

## 페이지로 나뉜 목록 살펴보기

### 템플릿, 데이터셋, 공유 파일, 모델, 이미지

1. 해당 목록을 열고 검색창과 제공된 필터로 결과를 좁힙니다. 페이지 조회는 검색, 필터링, 정렬 후 요청한 페이지를 반환하므로 검색 범위가 현재 페이지에만 한정되지 않습니다.
2. 목록 아래의 페이지 번호, 이전／다음, 페이지당 표시 개수 선택으로 결과를 살펴봅니다. 전체 개수는 현재 필터 조건에서 접근 권한이 있는 레코드 수입니다.
3. 템플릿, 데이터셋, 공유 파일, 모델 페이지에서는 검색, 소유자 필터, 정렬, 페이지당 개수를 변경하면 첫 페이지로 돌아갑니다. 템플릿 수정과 삭제에는 기존 권한 제한이 그대로 적용됩니다.

모델 첫 화면은 조직별로 묶어서 표시합니다. 조직을 열면 해당 조직의 모델을 볼 수 있습니다. 모델 페이지는 로컬 검색, 필터링, 페이지 나누기를 유지하며, 첫 화면의 전체 개수는 조건에 맞는 조직 수입니다.

계정 구성원 목록은 페이지별로 불러오며 사용자 이름 검색, 정렬, 역할 및 접근 모드 필터를 지원합니다. 데이터셋 공유 사용자 목록은 계속 전체 목록을 불러오고 페이지 내에서 검색, 정렬, 페이지 나누기를 수행합니다. 구성원을 추가하거나 데이터셋을 공유할 때는 선택 가능한 사용자 전체 목록을 표시합니다.

템플릿, 데이터셋, 공유 파일 목록은 읽기 요청이 실패해도 요청한 페이지 번호를 유지하고 “다시 시도”를 표시합니다. “다시 시도”로 다시 읽어 주세요. 실패 후 데이터나 전체 개수를 알 수 없는 상태는 조회가 성공했지만 결과가 0개인 상태와 다릅니다. 삭제로 현재 페이지가 최신 결과 범위를 벗어난 경우, 재조회에 성공하면 마지막 유효 페이지로 이동합니다.

### 노드 및 Pod 목록 보기

노드 목록, 노드 상세의 Pod, 일반 작업 상세의 Pod는 기존처럼 전체 목록을 읽습니다. 읽기에 성공하면 검색, 필터링, 정렬이 전체 목록에 적용되므로 먼저 “더 보기”를 누를 필요가 없습니다. 표의 기존 로컬 페이지 이동과 새로 고침 방식은 유지합니다. 검색에는 현재 유형 및 상태 필터가 적용됩니다. 다른 Pod를 찾으려면 필터를 변경하거나 해제하세요. 새로 고침하면 기존 기본 필터가 다시 적용됩니다.

각 스케줄러는 기존 Pod 읽기 API를 계속 사용합니다. 노드 Pod 관리자 화면은 작업, 사용자, 계정 및 잠금 정보를 유지하며, 일반 사용자 화면의 기존 조회 범위도 유지합니다.
