# TensorBoard 面板

Crater 可以从个人目录或已有作业的日志创建 TensorBoard 面板。入口位于个人面板页以及作业操作菜单。

## 写入日志

创建单机、Jupyter、WebIDE、PyTorch DDP 或 TensorFlow PS 作业时，可设置 `TENSORBOARD_LOGDIR`。默认目录由后端在作业创建后解析为 `/home/<用户>/tensorboard-runs/<唯一作业名>`，因此展示名称相同的作业也不会混用日志目录；自定义目录必须是绝对路径。

TensorFlow PS 模板默认由 worker-0（chief）写入摘要，避免多个 worker 重复写入同一事件流。

## 创建面板

1. 打开 **TensorBoard** 创建页。填写必填的 **面板名称**（1–40 个字符，支持中文）。名称可以重复；个人列表和删除确认显示名称与独立 ID，名称不改变日志目录、访问地址或权限。
2. 填写个人目录或点击 **浏览个人目录** 选择已有目录，也可选择当前用户拥有的作业作为来源。展开来源作业下拉列表，在顶部搜索框输入名称即可搜索全部历史作业；列表默认显示最近 50 条，每次最多显示 50 条匹配结果。选项同时显示用户名称和唯一作业 ID，支持按任一字段搜索；同名作业通过 ID 区分，切换搜索结果不会丢失已选作业的名称。
3. 可添加 0 到 10 个来源。多来源会分别挂载到 `/tensorboard-runs/<作业名>`，TensorBoard 会递归发现其中的 run。
4. 提交面板。它会进入你的调度队列，启动器开始运行后最多运行四天，也可能因长时间未访问提前结束。每位用户最多同时保有 10 个等待中或活动面板。

个人目录只能位于当前用户的 `/home/<用户>` 下。目录浏览支持进入子目录、返回上级、回到个人空间根目录及按名称筛选当前层子目录；点击 **使用当前目录** 会回填路径。浏览失败时可重试或取消后手动填写，创建面板不依赖目录浏览成功，也可先填写训练程序将创建的目录。

作业来源只能引用自己的作业及其允许的存储挂载，当前仍需手动填写或使用自动填入的日志目录，不支持浏览任意作业 PVC。目录浏览不检查 event 文件，请确认训练程序会向选定目录写入日志。

## 状态、访问与清理

默认连续 16 小时未访问即正常结束，管理员可调整空闲时限；重新访问会刷新空闲时间，但不会延长四天运行上限。健康探针不算访问，浏览器后台自动刷新算访问，因此关闭标签页后通常从最后一次请求开始计时。正常到期在集群和页面上均为 Completed，页面显示与普通作业相同的绿色“已完成”，并说明空闲或四天到期原因；列表“最晚到期时间”仅指四天上限。结束后停止服务，通常五分钟后清理资源；可以随时手动删除，不影响原始训练日志。新策略仅用于新建面板，旧面板需重建。

面板状态为 `pending`、`starting`、`ready`、`completed`、`failed` 或 `expired`，由 Volcano Job 阶段与 Pod Ready 条件判断；其中 `pending` 与普通 VCJob 的 Pending 阶段一致。它不代表 Service、Ingress 或 EndpointSlice 的独立健康检查。

打开面板时，Crater 会验证登录用户、面板是否仍存在以及面板所有权，再签发仅用于该面板路径的短期访问会话。单独获知面板 URL 不能绕过此校验。面板删除或自动回收后，URL 会随资源清理而失效。

## 常见问题

- 一直处于 `pending`：面板正在调度队列中等待兼容的 CPU 和内存资源，可联系管理员检查队列与节点容量。
- 一直处于 `starting`：联系管理员检查镜像拉取和 Pod 事件。
- 状态为 `failed`：查看面板错误信息；其中只返回安全的英文错误摘要，不包含集群内部细节。
- 页面可打开但没有曲线：确认选中的路径中存在 event 文件，并检查训练程序写入的实际目录。
