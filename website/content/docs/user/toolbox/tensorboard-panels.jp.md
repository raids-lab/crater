# TensorBoard パネル

Crater では、個人ディレクトリまたは既存ジョブのログから TensorBoard パネルを作成できます。個人パネル画面またはジョブの操作メニューから開始します。

## ログの出力

単一ノード、Jupyter、WebIDE、PyTorch DDP、TensorFlow PS の作成フォームで `TENSORBOARD_LOGDIR` を設定できます。デフォルト値はジョブ作成後にバックエンドで `/home/<user>/tensorboard-runs/<unique-job-name>` に解決されるため、表示名が同じジョブでもログは共有されません。カスタムディレクトリには絶対パスを指定してください。

TensorFlow PS テンプレートでは、同じイベントを重複して書き込まないよう、デフォルトで worker-0（chief）が summary を出力します。

## パネルの作成

1. **TensorBoard** 作成画面を開きます。
2. 個人ディレクトリを追加するか、現在のユーザーが所有するジョブを選択します。ジョブ一覧は全ページを読み込みます。
3. 0～10 個のソースを追加できます。複数のジョブは `/tensorboard-runs/<job-name>` 以下に別々にマウントされ、run は再帰的に検出されます。
4. パネルを送信します。スケジューリングキューに入り、Pod 起動後は最長 4 日間実行されます。1 ユーザーにつき待機中または稼働中のパネルは最大 10 個です。

個人ディレクトリは現在のユーザーの `/home/<user>` 以下に限られます。ジョブソースは自分のジョブと、そのジョブに許可されたストレージマウントだけを参照できます。作成画面はディレクトリ内容を検査しないため、event ファイルの存在を確認してください。

## 状態、アクセス、クリーンアップ

状態は `pending`、`starting`、`ready`、`failed`、`expired` です。Volcano Job の phase と Pod Ready 条件から判定し、`pending` は通常の VCJob の Pending phase と一致します。Service、Ingress、EndpointSlice を個別にヘルスチェックするものではありません。

パネルを開く際、Crater はログインユーザー、パネルの存在、所有権を確認し、そのパネルパス専用の短期アクセスセッションを発行します。URL を知っているだけではアクセスできません。削除または自動回収後はリソースが消え、URL も無効になります。

## トラブルシューティング

- `pending` のまま: スケジューリングキューで互換性のある CPU/メモリを待っています。管理者にキューとノード容量の確認を依頼してください。
- `starting` のまま: 管理者にイメージ取得と Pod イベントの確認を依頼してください。
- `failed`: 表示される安全な英語の概要を確認してください。クラスタ内部情報は返されません。
- グラフがない: event ファイルの場所と学習プログラムの出力先が一致するか確認してください。
