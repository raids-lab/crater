# TensorBoard パネル

Crater では、個人ディレクトリまたは既存ジョブのログから TensorBoard パネルを作成できます。個人パネル画面またはジョブの操作メニューから開始します。

## ログの出力

単一ノード、Jupyter、WebIDE、PyTorch DDP、TensorFlow PS の作成フォームで `TENSORBOARD_LOGDIR` を設定できます。デフォルト値はジョブ作成後にバックエンドで `/home/<user>/tensorboard-runs/<unique-job-name>` に解決されるため、表示名が同じジョブでもログは共有されません。カスタムディレクトリには絶対パスを指定してください。

TensorFlow PS テンプレートでは、同じイベントを重複して書き込まないよう、デフォルトで worker-0（chief）が summary を出力します。

## パネルの作成

1. **TensorBoard** 作成画面を開きます。 必須の **パネル名**（1～40 文字。日本語も使用可能）を入力します。同名を使用できます。個人一覧と削除確認には名前と独立した ID を表示し、名前はログのパス、アクセス URL、権限を変更しません。
2. 個人ディレクトリを入力するか、現在のユーザーが所有するジョブを選択します。ソースジョブのドロップダウンを開き、上部の検索欄に名前を入力すると全履歴を検索します。一覧は最初に最新 50 件を表示し、検索では最大 50 件の一致結果を表示します。 選択肢にはユーザーが付けた名前と一意のジョブ ID を表示し、どちらでも検索できます。同名ジョブは ID で区別でき、検索結果が変わっても選択済みの名前は保持されます。
3. 0～10 個のソースを追加できます。複数のジョブは `/tensorboard-runs/<job-name>` 以下に別々にマウントされ、run は再帰的に検出されます。
4. パネルを送信します。スケジューリングキューに入り、ランチャー起動後は最長 4 日間実行されますが、無アクセスにより早く終了する場合もあります。1 ユーザーにつき待機中または稼働中のパネルは最大 10 個です。

個人ディレクトリは現在のユーザーの `/home/<user>` 以下に限られます。ジョブソースは自分のジョブと、そのジョブに許可されたストレージマウントだけを参照できます。作成画面はディレクトリ内容を検査しないため、event ファイルの存在を確認してください。

## 状態、アクセス、クリーンアップ

デフォルトでは連続 16 時間アクセスがないと正常終了します。管理者はこの時間を変更できます。アクセスは無アクセス時間を更新しますが、4 日の実行上限は延長しません。ヘルスプローブは含まず、ブラウザーのバックグラウンド更新は含みます。タブを閉じた後は通常、最後の要求から時間を計測します。正常な期限切れではクラスタと画面の状態が Completed になり、通常ジョブと同じ緑色の「完了」と無アクセスまたは 4 日の期限切れ理由を表示します。「最終有効期限」は 4 日の上限のみを示します。終了後はサービスを停止し、通常 5 分後にリソースを回収します。手動削除はいつでも可能で、学習ログは削除しません。新しいパネルのみ対象となるため、既存パネルは再作成してください。

状態は `pending`、`starting`、`ready`、`completed`、`failed`、`expired` です。Volcano Job の phase と Pod Ready 条件から判定し、`pending` は通常の VCJob の Pending phase と一致します。Service、Ingress、EndpointSlice を個別にヘルスチェックするものではありません。

パネルを開く際、Crater はログインユーザー、パネルの存在、所有権を確認し、そのパネルパス専用の短期アクセスセッションを発行します。URL を知っているだけではアクセスできません。削除または自動回収後はリソースが消え、URL も無効になります。

## トラブルシューティング

- `pending` のまま：スケジューリングキューで互換性のある CPU/メモリを待っています。管理者にキューとノード容量の確認を依頼してください。
- `starting` のまま：管理者にイメージ取得と Pod イベントの確認を依頼してください。
- `failed`: 表示される安全な英語の概要を確認してください。クラスタ内部情報は返されません。
- グラフがない：event ファイルの場所と学習プログラムの出力先が一致するか確認してください。
